## Brief overview
These guidelines ensure strict adherence to the design specifications outlined in the project's main README.md file, which serves as the authoritative reference for all application design decisions.

## Design compliance requirements
- Always reference the README.md file at the project root for design specifications
- Follow design patterns, layouts, colors, typography, and component structures exactly as documented
- Treat README.md as the single source of truth for all visual and architectural design decisions
- Maintain consistency with the established design language throughout the application

## Divergence approval process
- If any proposed changes require deviating from README.md specifications, immediately halt development
- Request explicit user approval before proceeding with any design modifications
- Document the reason for divergence and proposed alternatives
- Only implement changes after receiving written confirmation from the user
- Update the README.md with the approved changes if confirmation is received

## Implementation workflow
- Review README.md design specifications before starting any development task
- Cross-reference designs during implementation to ensure accuracy
- Flag any conflicts between README specifications and implementation requirements
- Seek clarification when design specifications are unclear or ambiguous

## Quality assurance
- Verify that all implemented features match README.md descriptions precisely
- Conduct design compliance checks before marking tasks as complete
- Maintain a checklist of README.md requirements for each development cycle
